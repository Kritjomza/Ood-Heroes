# Summon and AFK Rewards Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver secure, replay-safe summoning and exact 10/20/30-minute AFK reward tiers with polished, accessible web-game presentation.

**Architecture:** Pure shared rules define reward tiers and runtime contracts; server-authoritative Supabase transactions own elapsed time, economy mutation, pity, and idempotency. React consumes validated typed results through explicit summon animation states and an exact AFK preview.

**Tech Stack:** TypeScript 5.9, React 19, Vite 8, Vitest, Testing Library, Node game server, PostgreSQL/Supabase, pgTAP, Playwright, CSS animations.

## Global Constraints

- AFK rewards are exactly: 10 minutes = 80 Gold, 10 Diamonds, 3 Shards; 20 minutes = 160 Gold, 20 Diamonds, 6 Shards; 30 minutes = 250 Gold, 35 Diamonds, 10 Shards.
- No reward is available below 10 minutes and elapsed AFK time is capped at 30 minutes.
- Diamonds use the existing `gem` currency.
- Shards are awarded to every hero in the active party.
- Client clocks and client-provided economy values are never trusted.
- Summon and AFK mutations must remain atomic and idempotent.
- Preserve React/Vite, Node server, Supabase authentication, persistence, and existing hero assets.
- Controls remain keyboard accessible, at least 44 by 44 pixels, localization-safe, and reduced-motion aware.
- Do not add multi-pulls, heroes, banners, purchases, or external art.
